fp-collector — Architecture Overview

Two-layer bot detection system · Kubernetes deployment

Why two detection layers?

Layer 1 — CrowdSec (network level)
Blocks IP addresses with a known bad reputation before the request even reaches the app. Works on crowd-sourced threat intelligence: if an IP attacked any server in the CrowdSec network, it gets flagged globally.

Analogy: a bouncer at the door with a global blacklist.
Layer 2 — Flask (application level)
Detects new or unknown bots that have no prior reputation — by analysing how they behave: do they run JavaScript? Do they have a real GPU? What does their ASN say?

Analogy: a test inside the venue that a real human passes but a bot fails.

Layer 2 — Application (Flask + JS Fingerprinting)
Flask App — Python 3.13 · port 5000
Step A — GET /fp-collector/login/ · Early server-side detection
Runs before any HTML is served. Checks the incoming IP:
  • Reverse DNS PTR — verifies if IP belongs to a known bot (Googlebot, Bingbot…)
  • ASN lookup via MaxMind GeoLite2-ASN — is the IP from a datacenter? (AWS, GCP, Azure, DO…)
  • Cloud IP ranges — direct comparison against known cloud CIDR blocks
  • User-Agent patterns — curl, python-requests, scrapy, headlesschrome…

→ Bot detected: HTTP 403 — never sees the page
→ Passes: render login page with JS fingerprint collector
Step B — Browser runs JS fingerprint (index.html)
JavaScript silently collects signals while the user sees a login form:
  • Hard signals (used for blocking): WebGL renderer, GPU benchmark duration, hw_concurrency, JS execution time, canvas hash
  • Soft signals (stored for analysis only): mouse moves, scroll events, keystroke timing, hesitations
All data is POSTed to /api/collect
Step C — POST /api/collect · Hard signal verdict
Flask checks hard signals only — things a bot cannot easily fake:
  • No WebGL / no GPU → headless browser
  • Virtual GPU string (swiftshader, llvmpipe, virtualbox…)
  • GPU benchmark > 5000 ms → running in a VM
  • JS execution < 5 ms → headless (no real rendering)
  • hw_concurrency = 0 → not a real machine
→ Bot: {"is_bot": true, "status": "blocked"} HTTP 403
→ Human: {"is_bot": false, "status": "ok"} HTTP 200

Request flow — step by step

1
Visitor (human or bot) sends a request to Traefik :80
2
CrowdSec bouncer (when activated) checks the IP against CrowdSec decisions — known bad IPs are blocked here at the network level, before Flask is involved
3
Traefik routes the request to Flask at :5000 and writes the access to access.log
4
Flask early detection (GET handler) checks reverse DNS, ASN, cloud IP ranges, UA pattern — bot → HTTP 403 / human → login page served
5
Browser JS collects fingerprint silently: WebGL GPU info, benchmark timing, hardware concurrency, canvas hash, mouse/scroll behavior
6
POST /api/collect — Flask evaluates hard signals. Bot → 403 + is_bot:true / Human → 200 + is_bot:false. Result saved to SQLite.
7
CrowdSec continuously reads Traefik access logs in the background — detects attack patterns and builds reputation decisions for future requests
